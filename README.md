# Пульт Android TV

Приложение для телефона, которое управляет телевизором на Android TV по протоколу Remote v2:
тот же канал, что использует штатный пульт Google TV. Протокол реализован с нуля на Kotlin,
интерфейс — Jetpack Compose, минимальная версия Android — 8.0 (API 26).

## Что умеет

- Спаривание по PIN-коду прямо в приложении, сертификат хранится в приватном хранилище телефона
- D-pad, OK (долгое нажатие — контекстное меню), питание, «Домой», «Назад», «Меню»
- Голосовой поиск: держите кнопку микрофона и говорите — телефон распознаёт речь и
  открывает поиск на телевизоре
- Громкость и переключение каналов качельками, отключение звука
- Управление воспроизведением, поиск, ассистент, настройки, источник сигнала, гид
- Цифровая панель, ввод текста в поле на экране телевизора, запуск приложений по id пакета
- Состояние телевизора в реальном времени: питание, громкость, текущее приложение
- Поиск телевизоров в сети по mDNS (`_androidtvremote2._tcp`)
- Кнопки громкости телефона управляют громкостью телевизора, пока приложение открыто
- Автоматическое переподключение после обрыва связи и выключения телевизора

## Сборка

Нужны JDK 17+ и Android SDK (platform 36, build-tools 36.0.0). Путь к SDK — в `local.properties`.

```bash
./gradlew :app:assembleRelease
```

APK появится в `dist/app-release.apk` (~3 МБ). Отладочная сборка — `assembleDebug`,
тесты — `test`.

Если путь к проекту содержит кириллицу, каталог сборки автоматически уводится в системный
temp: часть инструментов Android не переносит не-ASCII в путях — см. «Особенности» ниже. В
обычном пути сборка идёт в `build/`, как всегда.

## Установка на телефон

APK подписан отладочным ключом, поэтому ставится без Play Маркета:

1. Скопировать `dist/app-release.apk` на телефон (или `adb install -r dist/app-release.apk`)
2. Открыть файл и разрешить установку из этого источника
3. Запустить, ввести IP телевизора или выбрать его из найденных в сети
4. При первом подключении телевизор покажет код из шести символов — ввести его в приложении

Телефон и телевизор должны быть в одной сети Wi-Fi.

## Устройство кода

### Ключевые решения

**Клиентский сертификат отправляется всегда.** Телевизор запрашивает сертификат, не называя
знакомых ему удостоверяющих центров, поэтому штатный `KeyManager` решил бы, что подходящего
сертификата нет. `CertStore` подменяет его на такой, который всегда предъявляет наш
единственный сертификат.

**Серверный сертификат не проверяется.** Он самоподписанный, и сверить его не с чем;
подлинность устройства подтверждается PIN-кодом на экране. Так же устроена эталонная
библиотека `androidtvremote2`, по которой сверялась эта реализация.

**Отказ в аутентификации приходит по-разному, и оба случая ведут к спариванию.** По TLS 1.2
телевизор отвергает незнакомый сертификат прямо в рукопожатии, а по TLS 1.3 (именно его
согласует Android с этим телевизором) рукопожатие «проходит», и `certificate_unknown`
прилетает уже на первом чтении — внутри сессии. Поэтому `TvController.runSession` считает
признаком неспаренности любой обрыв до первого полученного сообщения, а не только ошибку
рукопожатия. Без этого приложение бесконечно переподключалось бы, не предлагая ввести код.

**Голос распознаёт телефон, а не телевизор.** Сначала было сделано «по протоколу»: звук с
микрофона уходит телевизору сообщениями `remote_voice_*`, а распознаёт он сам. На TCL BeyondTV
(прошивка 6.9.906821247) это не работает, и вот что выяснено на живом устройстве:

- бит `VOICE` в возможностях телевизор объявляет (`code1: 639`);
- приглашение `remote_voice_begin` он присылает только на `KEYCODE_SEARCH` (не на `ASSIST` и
  не на `VOICE_ASSIST`), причём перестаёт присылать после некорректного обмена — лечится
  только полной перезагрузкой телевизора;
- получив приглашение и звук, телевизор отвечает `remote_voice_payload`, ассистент на экране
  реагирует на звук, но слов не разбирает. Проверены 8 и 16 кГц, куски по 8 и 16 КБ, с
  паузами и без, речь синтезировалась в файл и отправлялась в реальном темпе;
- `remote_voice_begin` с `session_id: 0` телевизор отвергает через `remote_error`, а лишний
  `remote_voice_end` обрывает соединение.

Поэтому голосовой поиск устроен иначе: речь распознаёт сам телефон
([`SpeechToText`](app/src/main/java/com/sprit/tvremote/tv/SpeechToText.kt), системный
распознаватель), а телевизору уходит готовый запрос ссылкой
`vnd.youtube://results?search_query=…` — этот способ проверен и открывает YouTube с
результатами. Собственный поиск телевизора текст извне не принимает: поле ввода он не
объявляет, `remote_ime_batch_edit` не присылает.

Отправка звука по протоколу осталась в [`RemoteSession`](app/src/main/java/com/sprit/tvremote/tv/RemoteSession.kt)
— она корректна и покрыта диагностикой, на случай если другая прошивка её поймёт.

**Формат звука для протокола:** 16-битный PCM, моно, 8000 Гц, куски от 8 КБ до 20 КБ. Меньший
кусок телевизор игнорирует (дополняем тишиной), больший — рвёт соединение (делим).

**Секрет спаривания проверяется тестом.** `PairingSecretTest` сверяет результат с эталоном,
посчитанным библиотекой `androidtvremote2`: телевизор сравнивает секрет со своим, и любое
расхождение в порядке или представлении чисел означает отказ в спаривании.

### Диагностика против живого телевизора

`LiveTvProbeTest` проверяет протокол на настоящем устройстве — без `-PtvHost` пропускается:

```bash
./gradlew :app:testDebugUnitTest --tests '*LiveTvProbe*' -PtvHost=192.168.1.106
```

Пробам, которые ходят на телевизор как уже спаренный клиент, нужен каталог с парой
`cert.pem`/`key.pem` от спаренного устройства — он задаётся через `-PtvCert=…`. Без него
такие пробы пропускаются.

`probe` подключается уже спаренным сертификатом и печатает состояние телевизора,
`probeUnknownCertificate` показывает, как телевизор отвергает незнакомый сертификат,
`probePairingHandshake` доводит спаривание до запроса кода (телевизор при этом на секунду
покажет код на экране), `probeVoiceInvite` и `probeVoice` проверяют голосовой канал протокола,
`probeTextSearch` — открытие поиска ссылкой.

Для `probeVoice` можно подсунуть настоящую речь — файлом WAV 8 кГц / 16 бит / моно:

```bash
./gradlew :app:testDebugUnitTest --tests '*probeVoice*' -PtvHost=192.168.1.106 -PtvVoice=C:/tmp/voice.wav -PtvCert=C:/tmp/pairing
```

### Классы protobuf

Схемы `app/src/main/proto/*.proto` восстановлены из дескрипторов библиотеки `androidtvremote2`
(питоновская реализация того же протокола).
Java-классы по ним сгенерированы один раз и лежат в `app/src/main/java/com/sprit/tvremote/proto`,
плагин protobuf в сборке не участвует: `protoc` — нативная программа и не открывает файлы по
пути с кириллицей.

Если схемы изменятся, классы нужно перегенерировать вручную в каталоге с латинским путём:

```bash
protoc --proto_path=proto --java_out=lite:out proto/polo.proto proto/remotemessage.proto
```

## Особенности

- **Кириллица в пути проекта.** `android.overridePathCheck=true` снимает запрет AGP, а каталог
  сборки уводится в temp — с хешем пути в имени, чтобы две копии проекта не дрались за один и
  тот же каталог. В пути без кириллицы обе меры не срабатывают, сборка идёт обычным порядком.
- **Иконки.** `material-icons-extended` заморожен на версии 1.7.8 и в Compose BOM больше не
  входит, поэтому версия задана явно. Неиспользуемые иконки вырезает R8 при сборке release.
